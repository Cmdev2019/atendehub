# 00-Governanca — Governança do repositório

## Objetivo

Definir como o repositório é operado: quem decide o quê, com que ritual, sob quais convenções e com qual rastreabilidade.

## Responsabilidade

Guardar as regras que valem para **todas** as demais pastas. Em caso de conflito entre um documento aqui e qualquer outro, este prevalece.

## Conteúdo esperado

- Plano de reestruturação do repositório e seu status de execução
- Convenção de nomenclatura (pastas, arquivos, código, branches, commits)
- Guia de boas práticas para manter o repositório organizado
- Definição de Ready e Definition of Done
- Matriz RACI por área e política de code owners
- Política de exceções (quando é aceitável violar uma convenção, e quem aprova)

## Quem utiliza

Tech lead, arquitetos, qualquer pessoa que abra um PR.

## Quando utilizar

Antes do primeiro commit de quem entra no time; sempre que uma convenção for questionada.

## Quem pode alterar

Tech lead ou arquiteto, via PR com aprovação de pelo menos um outro mantenedor. Nunca por push direto.
