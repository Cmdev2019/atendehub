# 02-Requisitos — Requisitos

## Objetivo

Descrever o comportamento esperado do sistema em nível verificável, antes de virar código.

## Responsabilidade

Traduzir visão de produto em requisitos funcionais e não-funcionais testáveis. Todo requisito precisa de critério de aceite.

## Conteúdo esperado

- Requisitos funcionais por domínio
- Requisitos não-funcionais (desempenho, disponibilidade, segurança, acessibilidade)
- Regras de negócio (SLA, roteamento, janela de 24h, retenção)
- Critérios de aceite em formato Gherkin
- Matriz de rastreabilidade requisito → teste → release

## Quem utiliza

Product Management, engenharia, QA.

## Quando utilizar

Antes de estimar; durante o refinamento; ao escrever teste de aceitação.

## Quem pode alterar

Product Management com revisão obrigatória de engenharia e QA.

## Estado atual

O backlog Epic→Feature→User Story→Task com critérios de aceite está na Fase 4 do plano de evolução.
