# 31-Versionamento — Versionamento

## Objetivo

Documentar como versionamos código, API, banco e documentação.

## Responsabilidade

Garantir que "versão" signifique a mesma coisa para todo mundo e que a compatibilidade seja previsível.

## Conteúdo esperado

- Política de versionamento semântico e o que caracteriza cada incremento
- Estratégia de branches e fluxo Git
- Convenção de commits e de tags
- Versionamento de API e política de deprecação
- Versionamento de schema e de fluxos de automação

## Quem utiliza

Toda a engenharia.

## Quando utilizar

Ao criar branch, commit, tag ou release; ao decidir se uma mudança quebra compatibilidade.

## Quem pode alterar

Tech lead. A convenção é obrigatória e verificada por automação.

## Estado atual

Convenção vigente: Conventional Commits em português, com ID do roadmap no título.
